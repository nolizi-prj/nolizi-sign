### 3. Falsifiability & Invariant Coverage ([`L-006`](file:///home/m/dev/pumasi/lessons/L-006-tests-that-cannot-fail.md))

The frozen acceptance test suite in [`service/src/test/oauth-callback.test.ts`](file:///home/m/dev/pumasi-sign/service/src/test/oauth-callback.test.ts) (**A-500** through **A-506**) is structured to prevent false-green results:

- **Mitigation of L-006 Branch Conflation (§S2):**
  Because 5 distinct failure modes on the callback route return `302 → Location: /login`, every negative test explicitly asserts execution depth:
  - Asserts global `fetch` stub invocation (`stub.calls.length === 1` when reaching token exchange vs `0` when rejected before exchange).
  - Asserts state row consumption or preservation in `auth_codes`.
  - Asserts zero writes occurred in `users`, `sessions`, and `org_branding`.
- **Comprehensive Edge Case Coverage:**
  - **A-500 (§S2, §S7):** Parameter checking on authorize redirect, state row persistence with stored `next`, open-redirect sanitization (`https://evil...` and `//evil...` normalized to `/`), and callback form payload verification.
  - **A-501 (§S7):** Token exchange with `email_verified: true`, email lowercasing, branding initialization, and valid session cookie verification against `/api/auth/me`.
  - **A-502 (§S3, §S7):** Verifies that omitting `email_verified` admits the user and establishes an authenticated session.
  - **A-503 (§S7):** Verifies that `email_verified: false` is rejected post-exchange, state is consumed, and replay is prevented.
  - **A-504 (§S7):** Verifies that `tokenRes.ok` status is evaluated prior to parsing payload data.
  - **A-505 (§S7):** Verifies non-JSON, non-base64, truncated, and missing `id_token` payloads as well as email addresses lacking `@`.
  - **A-506 (§S7):** Verifies Microsoft `preferred_username` fallback, verbatim local-part name handling, unconfigured provider `503`, unknown provider `404`, and missing state/code rejections prior to token endpoint invocation.
- **Mutation Verification (§S7a):**
  Ten mutations (`M1`–`M10`) systematically confirm test sensitivity, including explanation of why `!email.includes('@')` subsumes `!email` (`M4`).
