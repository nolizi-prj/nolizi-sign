### 2. Edge cases the acceptance tests miss

- **The per-row `UPDATE` (§S2d) carries no `AND status = 'pending'` recheck**, unlike its own `SELECT`. I looked for a demonstrable failure and could not construct one: in workerd, once the sweep event is delivered, every `await` in the handler is a storage operation, so input gates make the SELECT→UPDATE→audit sequence atomic with respect to other requests on the single object (§S0.2's one DO), and the node harness is single-threaded. The worst interleaving input gates permit (sweep delivered at a non-storage await inside an in-flight `complete`) ends with `completed` as the final status and an `expired` audit row preceding it — an accurate record, not a destroyed one. Recommend the guard at build time as one cheap clause; it is not a failing path.
- **Server-side, nothing rejects a *past* `expires_at`** on create or PATCH — the SPA validates at entry ("The expiration date must be in the future," §S1a) and §S2d pins only the shape (`LIKE '____-__-__T%'`). So a draft held past its deadline and then sent expires within the hour. This is the intent's own sentence working as written ("the deadline the app asks for is the deadline the service keeps"), the sender has the correction pencil (§S3d) before sending and the Copy route after, so it is noted, not objected.
- §S2d never states what `?` binds to (current UTC ISO-8601, matching the lexicographic argument the same clause makes). Implementer-obvious.
