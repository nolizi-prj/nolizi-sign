### 3. Acceptance Test Invariants & Falsifiability ([`L-006`](file:///home/m/dev/pumasi/lessons/L-006-tests-that-cannot-fail.md))

The frozen acceptance test suite in [`service/src/test/oauth-callback.test.ts`](file:///home/m/dev/pumasi-sign/service/src/test/oauth-callback.test.ts) (cases **A-500** through **A-506**) provides comprehensive, deterministic coverage:

- **Mitigation of L-006 Branch Conflation (§S2):**
  Because 5 distinct failure conditions on the callback route return an identical `302 → Location: /login` response, each negative case explicitly verifies execution depth:
  - Asserts global `fetch` stub invocation (`stub.calls.length === 1` when reaching token exchange vs `0` when rejected beforehand).
  - Asserts state row consumption or preservation in `auth_codes`.
  - Asserts zero mutations occurred in `users`, `sessions`, and `org_branding` tables.
- **Coverage of Invariants:**
  - **A-500 (§S2, §S7):** Authorize redirect parameters, state row generation with stored `next`, open-redirect sanitization (`https://evil...` and `//evil...` normalized to `/`), and callback form payload verification.
  - **A-501 (§S7):** Successful token exchange with `email_verified: true`, email lowercasing, workspace branding initialization, and valid session cookie creation verifiable on `/api/auth/me`.
  - **A-502 (§S3, §S7):** Characterizes the finding that payloads omitting `email_verified` establish active authenticated sessions.
  - **A-503 (§S7):** Confirms `email_verified: false` is rejected after token exchange, leaving database state unmodified and spending the state token against replay attacks.
  - **A-504 (§S7):** Asserts `tokenRes.ok` status is evaluated prior to parsing payload data.
  - **A-505 (§S7):** Unparseable, non-JSON, and absent `id_token` payloads and email strings lacking `@` are safely rejected without crashing.
  - **A-506 (§S7):** Microsoft `preferred_username` fallback, verbatim local-part name handling, provider-unconfigured `503` responses, unknown provider `404`, and callback handling with missing state/code.

- **Mutation Verification (§S7a):**
  All ten worker mutations (`M1`–`M10`) were executed. Tightening the guard (`M1`) turns only A-502 red; dropping the verified guard (`M2`) turns only A-503 red; dropping status check (`M3`) turns only A-504 red; and dropping state deletion (`M6`) turns A-500, A-502, A-503, and A-504 red. M4's non-failing result is clearly explained by `!email.includes('@')` subsuming `!email`.
